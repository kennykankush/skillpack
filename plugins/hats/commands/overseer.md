Use the `overseer` role for: $ARGUMENTS

Follow `skills/overseer/SKILL.md`:

1. Set boundaries first: what you must not read, and which side you are on if you already crossed one.
2. Get ready: the project's rules, docs map, roadmap, current goal status, handover ledger, recent commits and trailers, running state, and each watched agent's latest log. Run `workbench:devour` when there is no usable map.
3. Show the situation card with freshness labels, then start watching.
4. Check claims before repeating them. Say reported or checked.
5. Relay only the user's own decisions. Never approve on their behalf, hold off when they talk to the agent directly, and report queued, acknowledged or verified.
6. Keep the decision queue and the watch log in the project so the next overseer inherits the context.
